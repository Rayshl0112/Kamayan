The saved evaluation disabled Python socket connections throughout local model loading and real-video inference. A separate executable test also prohibited socket connections during computer-clip recognition and passed. Local Windows voice synthesis produced real audio without a network voice service.

The browser trial allowed loopback HTTP and local blob URLs while denying every external HTTP request. The actual local downloaded MP4 → prediction → confirmation → speech playback workflow succeeded under those rules, and the saved browser reports recorded no external requests.

Together these checks verify locally loaded inference and the complete browser workflow without external network services. **The laptop's Wi-Fi was not physically disconnected during this recorded trial.** Describe the evidence as network requests blocked for the tested processes, rather than a machine-wide Wi-Fi disconnection test.

## Limits to retain in the demo

- The word classifier accepts a manually selected isolated sign; it does not translate continuous ASL sentences.
- A model score cannot certify a prediction. Users review top suggestions and confirm a word.
- Missing hands, poor lighting, motion blur, partial signs, unfamiliar signers, and unsupported words can produce uncertain or wrong outputs.
- The model's vocabulary is finite and comes from the actual label file.
- Windows desktop voices may sound different from Apple's voices. The app uses local Windows speech on this machine.
- Apple system fonts resolve only on devices with those fonts installed; Windows uses its system-font fallback.
- Third-party model and data rights restrict what may be packaged or published. Local test success does not resolve redistribution permission.
